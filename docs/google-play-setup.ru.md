# Настройка Google Play

Как разрешить storelingo читать (`pull`) и обновлять (`push`) карточки приложения в Google Play. Настройка делается один раз для аккаунта разработчика Google Play.

[English version](google-play-setup.md)

storelingo обращается к Google Play Android Publisher API от имени **сервисного аккаунта** — служебной учётной записи со своим JSON-ключом. Ключ не попадает в конфиг: storelingo читает его только из переменной окружения.

## 1. Проект Google Cloud и API

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте проект или выберите существующий. Подойдёт любой проект, привязывать его к приложению не нужно.
2. В этом проекте включите **Google Play Android Developer API** (найдите его в библиотеке API).

## 2. Сервисный аккаунт и JSON-ключ

1. В том же проекте создайте **сервисный аккаунт** (IAM и администрирование, Сервисные аккаунты). Роли Google Cloud ему не нужны.
2. Откройте сервисный аккаунт, создайте новый ключ типа **JSON** и скачайте его.
3. Не добавляйте файл в git. `storelingo init` уже дописывает `play-service-account*.json` в `.gitignore`, поэтому файл с именем вроде `play-service-account.json` игнорируется. Не коммитьте его, не вставляйте в чаты и не храните в репозитории.

Запишите e-mail сервисного аккаунта (он выглядит как `name@project-id.iam.gserviceaccount.com`) — он понадобится на следующем шаге.

## 3. Доступ сервисного аккаунта в Play Console

1. Откройте Play Console и перейдите в раздел **Пользователи и разрешения** («Users and permissions»).
2. Пригласите e-mail сервисного аккаунта как нового пользователя.
3. Дайте ему доступ к вашему приложению с разрешением редактировать данные о приложении в магазине (store listing). Выдавайте только то, что нужно для локализуемого приложения.
4. Сохраните. Разрешения могут применяться не сразу (иногда несколько часов). Если первый запуск завершился ошибкой `E_AUTH_PLAY`, подождите и повторите.

Названия пунктов меню в Play Console время от времени меняются; если вы не видите именно этих названий, ищите страницы управления пользователями и разрешениями для приложений.

## 4. Укажите storelingo путь к ключу

`STORELINGO_PLAY_SERVICE_ACCOUNT` содержит путь к JSON-файлу ключа или сам JSON (удобно для секретов в CI).

macOS / Linux:

```bash
export STORELINGO_PLAY_SERVICE_ACCOUNT=/path/to/play-service-account.json
```

Windows PowerShell:

```powershell
$env:STORELINGO_PLAY_SERVICE_ACCOUNT = "C:\path\play-service-account.json"
```

Имя пакета указывается в `storelingo.config.json` (его спрашивает `init`):

```json
{ "stores": { "play": { "packageName": "com.example.app" } } }
```

## 5. Первый запуск

```bash
npx storelingo pull            # скачать текущие тексты в fastlane/metadata/android
npx storelingo translate       # перевести изменившиеся поля исходника
npx storelingo check           # офлайн-проверка лимитов и обязательных полей
npx storelingo push --dry-run  # показать diff с живой карточкой, ничего не менять
npx storelingo push            # показать diff, спросить, затем загрузить
```

Что важно знать:

- `pull` только пишет файлы. Он не меняет магазин и не трогает `storelingo.lock.json`. Локальные файлы, отличающиеся от магазина, он оставляет, если не указан `--force`.
- У скачанных переводов нет записи в `storelingo.lock.json`, поэтому `translate` считает их ручными правками и пропускает. Чтобы перевести заново, запустите `translate --force` (добавьте `--locale <код>`, чтобы ограничиться некоторыми локалями).
- `push` сначала запускает `check` и останавливается при ошибках (код выхода 1). За один `push` создаётся одна правка (edit) Google Play, и она фиксируется с `changesInReviewBehavior=ERROR_IF_IN_REVIEW`, поэтому изменения, уже находящиеся на проверке, никогда не отменяются.
- Вне интерактивного терминала (CI, каналы) `push` требует `--yes` или `--dry-run`; это проверяется до любых сетевых запросов.
- Google проверяет изменения карточки перед публикацией.
- Список изменений (release notes) пока не загружается; используйте для него `fastlane supply`.
- Языки, которые есть только в Google Play, никогда не удаляются. Для нового языка нужны `title`, `short_description` и `full_description`.

## Решение проблем

| Ошибка | Вероятная причина | Что делать |
|---|---|---|
| `E_AUTH_PLAY` | Google отклонил ключ или у сервисного аккаунта нет доступа к приложению. Типичные причины: Google Play Android Developer API не включён в проекте Google Cloud, к которому относится ключ; сервисный аккаунт не приглашён в Play Console или у него нет разрешения редактировать данные о приложении в магазине; приглашение только что создано и ещё не вступило в силу. | Проверьте три шага выше, подождите после изменения разрешений и повторите. |
| `E_CONFIG` («app not found or not accessible» или сообщение про `STORELINGO_PLAY_SERVICE_ACCOUNT`) | Неверный `stores.play.packageName` или приложение недоступно сервисному аккаунту; либо переменная окружения не задана, либо путь/JSON некорректны. | Проверьте имя пакета и доступ сервисного аккаунта к приложению; проверьте переменную и что файл читается. |
| `E_IN_REVIEW` | Изменения этого приложения уже находятся на проверке в Play Console. storelingo их не отменяет и ничего не изменил. | Дождитесь окончания проверки либо отправьте или отмените ожидающие изменения в Play Console и повторите `push`. |
| `E_STORE` | Другая ошибка API Google Play (HTTP-ошибка, неожиданный ответ, сбой сети после повторов). | Прочитайте сообщение. Если в нём «commit status is unknown», на последний запрос не пришёл ответ: проверьте Play Console или запустите `push --dry-run`, чтобы увидеть, совпадает ли карточка с вашими файлами. |

Коды выхода: `0` — успех; `1` — ошибка выполнения, ошибки `check` или заблокированный `push`; `2` — неверное использование или конфиг (например `E_CONFIG`, либо `push` без `--yes` вне терминала).
